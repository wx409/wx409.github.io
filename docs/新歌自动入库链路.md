# 新歌自动入库链路（2026-10-29 建成）

> 目标：新歌**发出来就自动进采集清单、发行表、时间轴**，不再需要人工点名。

## 一、链路总览

```
每日 auto_update（--watch）
  ① watch_releases.py --apply       QQ 音乐搜「王晰」→ diff → 正式作品入库（albums/songs_meta）
  ② watch_netease.py --apply        网易云补漏（独家/首发）
  ③ fetch_tour_weibo.py             巡演号增量（顺带发现新场次）
  ④ auto_song_intake.py             ★ 新增：写入三个落点
        · 采集清单  E:\wx\收听人数（2026.7.24）.xlsx
        · 发行表    E:\wx\index_records\王晰歌曲信息汇总.xlsx（OST&单曲）
        · 时间轴    data/timeline.json
  ⑤ scan_intake.py                  官宣扫描 → 候选箱（演出/活动） 
  ⑥ deploy_all.py                   重建页面 + 审计 + 推送
```

### 之后的自动环节

```
次日 18:05 采集批次读采集清单 → 火光在列 → 抓 QQ 指数
→ dashboard_data.json 自动更新 → 大屏 / 数据时间线出现曲线
```

## 二、auto_song_intake.py 的规则

| 规则 | 说明 |
|---|---|
| 只处理**单曲** | `albums.json` 中 `kind=single` 的曲目；专辑曲目不进 OST/单曲表 |
| 幂等 | 已存在（同名）则跳过，可反复运行 |
| 先备份 | 两个 xlsx 写入前自动 `.bak_时间戳` |
| 占用不丢 | 文件被 Excel 占用时进 `data/intake_queue.json`，下次运行自动补 |
| 留痕 | 每次运行写 `data/song_intake_log.json` |

## 三、实测

- 2026-10-29 运行：采集清单 384 → **385 行**（火光），发行表已含火光，时间轴已有条目；
- `watch_releases` 当日检索 56 条，新增正式作品 0（无新歌），链路空跑正常；
- 新歌出现时，下一次 `auto_update` 会自动完成 ①→④。

## 四、仍需人工的两处（诚实标注）

1. **QQ 指数延迟**：新歌发行后 3–7 天才有指数；链路会自动采，但数据要等；
2. **火光的采集清单行**是本次人工补的（因为链路当时还没建成）——之后不需要了。

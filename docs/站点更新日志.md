## 2026-09-02 · city 字段校准（数据层根治）

**背景**：筛选条暴露 city 字段 14 条异常，根因是生成器 `_city_of_name` 从场次名反推城市时，括号分支误判「演出名·城市（备注）」格式。

**落地**：
| 项 | 说明 |
|---|---|
| 新增 `_clean_city()` | 直接清洗「地点」列：去括号备注（「北京（CCTV-1）」→「北京」）、识别「—」等待补标记、场馆/演播厅词→城市待补 |
| 演出活动表直传 city | `load_performance_events` 存入清洗后 city，`tour_song_effects` 优先用它（`if "city" in info`），不再从 scene 反推 |
| 修 `or` 陷阱 | 原 `info.get("city") or _city_of_name(scene)` 把空串当 falsy 误 fallback，改为显式 `in` 判断 |
| 待补占位 | 城市为空时前端渲染「待补」（`.tse-city-na` 灰色斜体），筛选条不出现待补 chip |

**结果**：异常 city 清零（北京/上海/南宁等恢复正常，央视演播厅、电视录制等无固定城市场次如实标记「待补」）；`_city_of_name` 仍服务巡演长表。

## 2026-09-01 · 修复：dashboard_data.json 含 NaN 导致页面数据加载失败

**现象**：数据大屏动态区块全部不渲染（浏览器严格 `JSON.parse` 遇 `NaN` 字面量报错 → `dashboardData=null`）。

**根因**：生成器 `json.dump` 默认 `allow_nan=True`，某场次 `trend_raw[44]` 含 NaN（Python 的 json 解析宽容、浏览器严格）——本地/线上 JSON 均无法被浏览器解析。

**修复**：
| 文件/模块 | 说明 |
|------|------|
| 大屏生成器（快照→`project_b/`） | 新增 `_clean_nan()` 递归清洗（NaN/Infinity→null），`dashboard_data.json` 与 `dashboard_lite.json` 写盘前统一应用 |
| 验证 | 严格 JSON 解析通过（`parse_constant` 拦截法）；headless Edge 实测页面渲染恢复（tour-scene 场次全部出现） |

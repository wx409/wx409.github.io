# 转写与字幕校正说明（v1，2026-11-01）

## 一、两条路，成本差 40 倍

| 方案 | 做法 | 31 分钟视频耗时 | 准确率 | 什么时候用 |
|---|---|---|---|---|
**A. 音频转写** | faster-whisper turbo 本地转写 | **3–8 分钟** | 专名易错（王晰→王熹/王熙） | **默认用这个** |
**B. 硬字幕 OCR** | 抽帧（1 帧/秒）→ GOT-OCR → 与转写对齐 | **约 20 分钟** | 字幕也错（不说→不诡） | **只在要引用原话的关键访谈上用** |

**判断标准**：这条稿子要不要**逐字引用**？要 → B；只是了解内容 → A。

## 二、B 站视频有没有 CC 字幕，先查再说

```powershell
python -X utf8 project_b\fetch_bili_subtitle.py
```

- 输出 `字幕轨 N` —— N>0 说明有官方/CC 字幕，**直接下 JSON，成本几秒**
- 输出 `字幕轨 0` —— 没有字幕，你看到的字幕是**烧在画面里的**，才需要走方案 B

**实测**：`BV1GJFYeuEpb`（流水纪独家专访王晰）没有 CC 字幕，硬字幕。

## 三、方案 B 的完整步骤

```powershell
# 1) 下载视频（480p 足够，1080p 需大会员）
python -m yt_dlp --ffmpeg-location <ffmpeg> --cookies E:\wx\index_records\bilibili_cookies_netscape.txt ^
  -f "bv*[height<=480]+ba/b[height<=480]" --merge-output-format mp4 -o "temp\bili_full.%(ext)s" <视频URL>

# 2) 抽字幕带（关键：位置和放大倍数）
ffmpeg -i temp\bili_full.mp4 -vf "fps=1,crop=iw*0.80:ih*0.14:0:ih*0.80,scale=iw*2:-1" -q:v 2 temp\band\b_%04d.jpg

# 3) 批量 OCR（模型只加载一次）
python -X utf8 project_b\ocr_subtitle_frames.py temp\band 0 1 sub2

# 4) 清洗 + 与转写对齐 + 出差异表
python -X utf8 project_b\merge_subtitle_asr.py temp\band\sub2.json <转写txt> bili
```

### 抽帧参数为什么是这几个

| 参数 | 值 | 原因 |
|---|---|---|
裁剪高度起点 | `ih*0.80` | 字幕在 80%–94% 高度；抓高了会把人物衣服 OCR 成字母 |
裁剪高度 | `ih*0.14` | 只取字幕带 |
裁剪宽度 | `iw*0.80` | 右侧 20% 是台标/水印（「音乐流水纪」），不裁会污染 |
放大 | `scale=iw*2` | 480p 下字幕约 20px，放大后 OCR 准确率明显提升 |
帧率 | `1 帧/秒` | 字幕平均停留 2–4 秒；1 帧/秒够用，2 帧/秒会把时间翻倍 |

## 四、已知坑（都踩过）

1. **`proc([[img]])` 会报 `Nested images are only supported with multi_page`** —— 必须 `proc(img, ...)`
2. **直接 `model.generate` 会吐出 system prompt** —— 必须带 `tokenizer=` 和 `stop_strings`，参考 `run_ocr.py` 的 `ocr_image()`
3. **字幕 OCR 会读出台标和水印**（`NAKED` `GOLD` `LUMIX` `LH111_0_4`）—— 已在 `merge_subtitle_asr.py` 过滤
4. **OCR 也会错专名**（不诡/你扰/税我们…）—— 只能靠**两边交叉验证**，不能盲信任一边

## 五、结论：别把 B 当常规手段

- 日常：**A**（turbo 转写 + 19 条专名纠正规则）
- 关键：**B**（先查 CC 字幕，没有才 OCR）
- 引用的句子：**人工听一遍**，别跳过

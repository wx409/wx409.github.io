# 采编规范（v1，2026-11-01）

> 目的：让新采到的访谈、歌词、现场 talk **能直接进词句库**，不用再人工二次整理。

## 一、访谈：用 Q&A 格式，说话人写在冒号前

**标准写法**（这是唯一推荐格式）：

```
主持人：欢迎王晰来到节目，《声入人心》让更多人认识了你，现在生活和工作有哪些变化？
王晰：变化肯定是有的，舞台变多了，也被更多观众熟知，但我对音乐的心态一直没变。
```

**为什么这样写**：
- 脚本可直接抽「王晰：」后的内容 → **说话人 100% 准确**，不用猜
- 主持人问句自成一类，可单独做「问题库」，也可丢弃
- 段落之间不用空行规则，只要每段以「角色：」开头

**文件放哪**：`E:\wx\私有\王晰全文库\采访目录\全文\<媒体>_<年份>_<标题>.txt`

**导入命令**：`python -X utf8 project_b\import_liuyao_texts.py`（现成的问答抽取器，改路径即可复用）

### 允许的替代写法（效果次之）

| 写法 | 结果 |
|---|---|
Q&A（推荐） | 说话人准确，可自动切句 |
整篇散文（记者稿） | 只能抽引号内的话，**专名容易错** |
纯转写（ASR） | 需说话人切分，**准确率约 70%** |

## 二、歌词：一行一句，整首存，短句入池

**文件格式**：

```
【歌名】
第一行歌词
第二行歌词

【下一首】
...
```

**入池规则**（脚本已实现，`project_b\import_lyrics_full.py`）：
- 按【】分段，**每行作为一句**
- 只收 8–34 字；跳过纯语气行（啊/哦/嗯）
- 全库去重
- **`rights=仅内部`**，`type=lyrics`

**版权纪律（硬性）**：

| 可以 | 不可以 |
|---|---|
站内引用**短句**（≤2 行） | 整首成集、可检索全文 |
骰子抽单句 + 标歌名 | 批量导出歌词 |
统计（词频、主题） | 声称「歌词库」对外分发 |

## 三、现场 talk：必须人工过一遍，否则不入骰

现场转写是 ASR 输出，**断句与用词错误率高**。流程：

1. 转写 → `transcribe.py`
2. 说话人切分 → `split_speakers2.py`（出 `_王晰.md`）
3. **人工/半自动修订** → `data/talk_fixes.json`（左=原句，右=修订句，空串=丢弃）
4. 应用 → `python -X utf8 project_b\apply_talk_fixes.py`

**没有第 3 步，就不要让句子进骰子。** 宁可少，不放烂句。

## 四、质量分层口径

| 层 | 含义 | 能否进骰 |
|---|---|---|
`high` | 成句、有信息量、来源可信（文字稿/人工整理） | ✅ |
`mid` | 可读但未校对（转写、未核引语） | ❌ 暂不进 |
`low` | 碎片、口水、语义不完整 | ❌ |

## 六、新增一条素材的标准流程（2026-11-01 起）

### 情况 A：手里只有一个微博/视频链接

`
操作中心 259（一条链接全流程）
  → 输入链接
  → 输入出处（节目名 + 日期）
自动依次执行：
  ① transcribe.py --weibo      下载 + turbo 转写
  ② split_speakers2.py         分出「王晰 / 主持人 / 混合 / 未定」
  ③ add_phrases_from_file.py   切句入池（quality=mid）
  ④ build_phrases_page.py      重建词句页
然后手动或按 251 检查；满意后再：
  python -X utf8 project_b\curate_interview_pool3.py    # 重挑骰面
`

### 情况 B：手里是一段文字（手摘金句、整理稿）

`
操作中心 260（从文本文件入池）
  → 文件路径（.txt / .md 均可，一行一句或整段都行）
  → 出处
`
默认 quality=mid；确认可信时改 --quality high（会进骰池）。

### 情况 C：整理访谈（推荐用 Q&A 格式）

按 docs/采编规范.md 第一节写成「王晰：……」→ 用 import_liuyao_texts.py 的同一逻辑抽取，
**说话人零误差**，比转写可靠得多。

## 一、站点定位与架构

**定位**：围绕华语流行男低音歌手王晰构建的 GEO（生成式引擎优化）数字档案站——让"王晰"这一文化实体在中文互联网上可查、可问、可引用、可验证。

**架构四层**：

```
数据层（单一数据源）     构建层（Python 脚本）      页面层（静态 HTML）       发布层
cities.json            → build_*.py          → index / songs / 搜索等    → deploy_all.py
setlists.json          → watch_*.py（自动）    → live / map / tavern      → git push
songs_meta.json        → deploy_all.py       → dashboard / story         → IndexNow
...（见第二节）                              （JSON-LD 结构化）
```

**核心纪律（任何时候都不可违反）**：
1. 不写死数字：页面统计全部由脚本从 JSON 计算注入
2. 单一数据源：长表 xlsx（巡演歌单）→ cities/setlists → 页面
3. 敏感文件不进 git：radio_proxy.py、radio_cookie.json、.env、secrets.bat、音频、notify_config.json
4. 诚实披露：查不到标"待补"，绝不伪造
5. 零后端、零商业

## 四、常用操作手册

### 4.1 全量部署发布（改动数据/页面后必做）

```bat
cd D:\wx409.github.io
python project_b\deploy_all.py            :: 12 步：生成全部页面 + 敏感文件扫描 + commit + IndexNow
git push origin main                      :: 手动推送（沙箱/受控环境 ssh 受限）
```

> `deploy_all.py` 自带：敏感文件预警（radio_proxy/cookie/.env/音频 → 中止）、IndexNow 通知。
> 只想生成不提交：`python project_b\deploy_all.py --no-git`；自定义提交信息：`--commit "说明"`。

### 4.2 新歌自动入库（日常无需操作）

计划任务每日 08:30/20:30 自动执行：
1. `watch_releases.py --apply`：QQ 搜"王晰"→ diff → 新歌自动入库（带 mid/uid）→ 微信通知你
2. 自动抓歌词 + 创作班底
3. 自动构建 + 发布 + 通知

手动执行一次：`python project_b\watch_releases.py --apply`
只查看不入库：`python project_b\watch_releases.py`（输出到 `data/pending_releases.json`）
综艺现场版（(Live)）默认不进库，单独列清单。

### 4.3 歌词/创作班底补全


```bat

:: 4) 歌单曲目：待演出结束后录入长表 xlsx → 跑 build_setlists.py
```

## 五、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面"数据加载失败" | JSON fetch 失败/缓存 | 硬刷新（Ctrl+Shift+R）；检查 data/ 文件存在 |
| 歌曲点试听无反应/慢 | 网络/CDN 缓存 | 重试；player_embed.js?v=3 缓存键 |
| 搜索缺新歌 | site_search_index 未重建 | 重新生成索引（4.9） |
| 自动任务没跑 | 计划任务未装/电脑关机 | 双击安装 bat；检查 logs/ 日志 |
| push 失败 | 网络/凭据 | `git push origin main` 重试；看报错 |
| 部署被中止 | 检测到敏感文件在工作区 | 删除 radio_proxy/cookie/.env/音频后再跑 |
| 微信没收到通知 | SendKey 未配置/每日 5 条超限 | 检查 notify_config.json；次日再试 |
| 数字与数据不符 | 页面未重建 | 跑对应 build 脚本（第二节表格） |

**日志位置**：`logs/auto_update_YYYYMMDD.log`

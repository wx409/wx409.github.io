# 双机部署方案 · 笔记本 + 台式机（周末模式）

> **场景**：笔记本（现主力）工作日运行采集；台式机（i5-13600KF / 64G / RTX4070Ti）周末运行，周末不用带笔记本回家。
> **核心原则**：**同一时刻只有一台机器在采集**（星期分片）；**唯一事实源（长表）单向同步**；**网站仓库经 GitHub 双端 push（自动 pull-rebase 防冲突）**。
> **适用版本**：2026-08 现状（采集 382 首 / 18 批次 / 23:55 终批 / 00:10 关机）

---

## 〇、双机分工总览

| 项目 | 笔记本（现役） | 台式机（新增） |
|---|---|---|
| 采集运行日 | **周一 00:00 ~ 周五 23:59** | **周六 00:00 ~ 周日 23:59** |
| 采集程序 | `E:\wx\QQ音乐大屏生成器_GEO优化版_源码.py` | 同左（路径一致） |
| 数据目录 | `E:\wx`（保持现状） | `E:\wx`（**镜像笔记本**） |
| 网站仓库 | `D:\wx409.github.io` | `D:\wx409.github.io`（git clone） |
| 自动关机 | 工作日 00:10 | 周末 00:10 |
| 长表修改 | ✅ 唯一写入者 | ❌ 只读（改前先同步笔记本版本） |

**冲突规避三板斧**：
1. **星期分片**：采集脚本入口检查当天星期，非本机值班日直接退出（见 §6 切换脚本）
2. **git pull-rebase**：auto_deploy / music-index push 前先 `git pull --rebase`，双端 push 不冲突
3. **长表单向流**：只允许笔记本改长表 → 台式机通过同步工具拿到最新版（见 §4）

## 三、计划任务部署（台式机）

### 3.1 采集自启任务（登录触发，**带星期检查**）
```powershell
# 创建任务（先建脚本，见 §6）
schtasks /create /tn "QQMusicDashboardAutoStart" /tr "pythonw.exe E:\wx\run_scheduler_weekend.py" /sc onlogon /rl highest /f
```
> 关键：**用 `run_scheduler_weekend.py` 包装**（§6 提供），它内部检查"今天是周六/周日才真正启动采集"，否则直接退出。这样即使台式机周一~周五开机也不会误采集。

### 3.2 音乐周报任务（每天 23:58，带星期检查）
```powershell
schtasks /create /tn "wx409_music_index_daily" /tr "python D:\wx409.github.io\project_b\build_music_index.py --wait --push" /sc daily /st 23:58 /f
```
> `--wait` 模式自带"等 23:50 后末批数据"逻辑；周六/周日台式机采集 → 周报正确生成；工作日台式机不采集 → 数据未更新，脚本 `--wait` 到 00:08 超时会**跳过**（不会推旧数据，符合纪律）。

### 3.3 定时关机任务（周末 00:10）
```powershell
schtasks /create /tn "星厂定时关机" /tr "shutdown /s /t 60" /sc weekly /d SAT,SUN /st 00:10 /f
```
> **注意**：笔记本的"星厂定时关机"应改为**仅工作日**（周一~周五 00:10）——见 §6 切换脚本一键调整。

### 3.4 笔记本计划任务调整（防冲突，关键！）
| 任务 | 笔记本现配置 | 改为 |
|---|---|---|
| `QQMusicDashboardAutoStart` | 登录触发直接跑 | 登录触发跑 `run_scheduler_weekday.py`（周一~周五才采集） |
| `wx409_music_index_daily` | 每天 23:58 | **保持每天**（工作日笔记本有数据；周末台式机数据通过 Syncthing 同步过来后，笔记本 23:58 也能生成——见 §4 数据流说明） |
| `星厂定时关机` | 每天 00:10 | 改为**周一~周五** 00:10 |

## 四、数据同步（Syncthing）—— 双机数据一致的核心

### 4.1 为什么需要同步
笔记本工作日采集的 Excel（指数vs/download/指数数据库）**必须流到台式机**，台式机周末采集的 Excel **必须流回笔记本**——否则任一端的 merge_cache 重建后历史数据不完整，大屏数字会"倒退"。

### 4.2 同步方案（Syncthing 双向，P2P 无需云盘）

| 同步文件夹 | 方向 | 说明 |
|---|---|---|
| `E:\wx\指数vs` | 双向 | 采集输出，文件名带时间戳，天然不冲突 |
| `E:\wx\download` | 双向 | 同上 |
| `E:\wx\指数数据库` | 双向 | 同上 |
| `E:\wx\指数` | 双向 | 历史归档（首轮后增量极少） |
| `E:\wx\index_records\历次巡演歌单` | **单向：笔记本 → 台式机** | 长表唯一事实源，只允许笔记本写 |
| `E:\wx\index_records`（部分） | 双向 | `merge_cache.pkl`、`王晰歌曲信息汇总.xlsx`、`收听人数*.xlsx` 等 |

**配置步骤**：
1. 两台都装 Syncthing，添加彼此设备（Device ID 互换）
2. 在笔记本添加上述文件夹并共享给台式机
3. 台式机接受共享（存放到 `E:\wx` 对应路径）
4. 设置：
   - 冲突处理：**"保留两个版本"**（文件名带 `.sync-conflict-` 后缀）——采集文件不会冲突，长表若意外双改会留冲突副本供人工判断
   - `raw_archive` **不要同步**（22GB 无意义）

### 4.3 关键文件同步策略
| 文件 | 策略 | 原因 |
|---|---|---|
| `merge_cache.pkl` | 双向同步 | 增量缓存，两台各自 rebuild 会更新它；双端时间戳接近时可能小冲突，保留双版本可接受（重建成本 ~1 分钟） |
| 长表 xlsx | **单向 笔记本→台式机** | 唯一事实源，杜绝双写 |
| 链接清单 xlsx | 单向 笔记本→台式机 | 加歌只在笔记本做 |
| `QQ音乐大屏生成器_源码.py` | 双向 | 改源码两台都要（改前先同步） |

## 五、冲突预防细则（重要）

### 5.1 git push 冲突（双端都 push 同一仓库）
**现状**：auto_deploy 直接 `git push`，若两台几乎同时 push 会撞 `index.lock` 或 non-fast-forward。
**方案**：给笔记本和台式机的 auto_deploy 前加 `git pull --rebase`：
```python
# 源码 auto_deploy() 中 push 前插入
subprocess.run(["git", "pull", "--rebase"], cwd=REPO, capture_output=True, timeout=60)
```
> 由于**星期分片**保证同一时刻只有一台在采集，push 基本不会同时发生；pull-rebase 是双保险。

### 5.2 采集数据双写
**星期分片已解决**：`run_scheduler_weekday.py`（笔记本）只在周一~周五运行；`run_scheduler_weekend.py`（台式机）只在周六~周日运行。两台都开机时也不会双采。

### 5.3 长表双改
**纪律**：长表永远只在笔记本改。台式机如需看最新版 → Syncthing 自动同步（单向）。

### 5.4 定时关机冲突
笔记本：工作日 00:10 关机；台式机：周末 00:10 关机。互不干扰。周末台式机关机后，Syncthing 离线（数据已在关机前同步完——采集 23:55 结束，关机 00:10，有 15 分钟同步窗口；若担心，可在终批后加一条"同步完成后关机"脚本，见 §6.4）。

## 六、切换脚本（部署时生成，防冲突核心）

### 6.1 `E:\wx\run_scheduler_weekday.py`（笔记本用）
```python
# -*- coding: utf-8 -*-
"""笔记本采集入口：仅周一~周五运行"""
import subprocess, sys
from datetime import datetime

if datetime.now().weekday() >= 5:   # 5=周六, 6=周日
    print("[SKIP] 周末，笔记本不采集（台式机值班）")
    sys.exit(0)
subprocess.run([sys.executable, r"E:\wx\QQ音乐大屏生成器_GEO优化版_源码.py"])
```

### 6.2 `E:\wx\run_scheduler_weekend.py`（台式机用）
```python
# -*- coding: utf-8 -*-
"""台式机采集入口：仅周六~周日运行"""
import subprocess, sys
from datetime import datetime

if datetime.now().weekday() < 5:    # 0-4 = 周一~周五
    print("[SKIP] 工作日，台式机不采集（笔记本值班）")
    sys.exit(0)
subprocess.run([sys.executable, r"E:\wx\QQ音乐大屏生成器_GEO优化版_源码.py"])
```

### 6.3 一键切换脚本（可选，手动接管时用）
`E:\wx\switch_owner.bat`（在**当前值班机**上运行，用于节假日等特殊安排）：
```bat
@echo off
rem 用法: switch_owner.bat <laptop|desktop>
if "%1"=="laptop" (
    echo 启用笔记本采集，禁用台式机采集
    schtasks /change /tn "QQMusicDashboardAutoStart" /enable
    REM 台式机需远程或手动执行相反操作
) else (
    echo 启用台式机采集，禁用笔记本采集
    schtasks /change /tn "QQMusicDashboardAutoStart" /disable
)
```
> 跨机控制需远程（如 ToDesk/向日葵），日常靠**星期分片自动切换**，此脚本仅节假日备用。

### 6.4 同步完成后关机（可选增强）
`E:\wx\shutdown_after_sync.ps1`（台式机，终批后等 Syncthing 同步完再关机）：
```powershell
# 23:55 终批后调用：等 15 分钟让 Syncthing 完成同步，再关机
Start-Sleep -Seconds 900
shutdown /s /t 30
```

## 九、风险与回退

| 风险 | 影响 | 对策 |
|---|---|---|
| 周末台式机采集失败（Edge/网络） | 周末数据缺失 | 手动 `--once --quick` 重试；日志看 `qqmusic_dp_edge.log` |
| Syncthing 冲突文件 | 数据重复/覆盖 | 采集文件名带时间戳基本不冲突；长表单向不同步 |
| 双机同时 push | git 冲突 | 星期分片已避免；auto_deploy 加 pull-rebase 兜底 |
| 台式机首次 merge_cache 重建慢 | rebuild ~19 分钟 | 首次后 merge_cache 增量，~1 分钟 |
| 笔记本/台式机时间不同步 | 批次时间戳错乱 | 两台都开启"自动设置时间" |

# 小红书/微博/抖音间接聚合渠道技术调研

> 目标：在"纯 urllib、无浏览器、无签名逆向"前提下，为「王晰数字档案站」（纯静态 GitHub Pages，零后端）调研可程序化聚合微博/抖音/小红书关于"王晰"公开信息的合法渠道。
> 调研时间：2026-08-18。结论均需落地前实测复核。

## 一、结论速览

| 渠道 | 结论 | 首选方式 |
|---|---|---|
| 微博 | ✅ 有条件可行 | 移动端 JSON 搜索接口（免登录） |
| 抖音 | ⚠️ 搜索不可行，热榜可行 | 抖音热榜 JSON（零签名） |
| 小红书 | ❌ 不可行 | 无可靠间接渠道 |
| 头条 | ⚠️ 搜索需签名，热榜可行 | 头条热榜 JSON（免签名） |
| Bing | ✅ 现有方案继续 | 扩展关键词组 |

## 二、各渠道具体接口

### 微博（P0，最值得做）

- **移动端搜索 JSON（首选，免登录）**：
  `https://m.weibo.cn/api/container/getIndex?containerid=100103type%3D1%26q%3D王晰&page_type=searchall`
  （`100103type=1&q=王晰` 需整体 URL-encode）
- **用户主页时间线（需 uid）**：`https://m.weibo.cn/api/container/getIndex?type=uid&value={uid}&containerid=107603{uid}`
- **热搜榜 JSON**：`https://weibo.com/ajax/side/hotSearch`（需匿名 cookie）
- **搜索引擎间接（补充）**：Bing `site:weibo.com 王晰`（现用）；百度/搜狗反爬极强，不建议

解析：`data.cards[].mblog` 取 `id/text/created_at/user.screen_name/urls`，翻页用 `since_id`。

### 抖音（搜索不可行，热榜可行）

- 网页版搜索需 `a_bogus` 签名（逆向，**不做**）
- **抖音热榜 JSON（零签名）**：`https://www.iesdouyin.com/web/api/v2/hotsearch/billboard/aweme/`
- **头条热榜 JSON（零签名）**：`https://www.toutiao.com/hot-event/hot-board/?origin=toutiao_pc`

### 小红书（不可行）

- robots.txt 禁止搜索引擎抓取，`site:xiaohongshu.com` 收录极少
- 微信搜一搜只能搜公众号，无法定向小红书
- 网页版需 `x-s/x-t` 签名 + 登录 cookie，逆向不做
- 第三方（新榜/清博/蝉妈妈）付费 SaaS，个人站性价比低

### 通用渠道（可做）

- RSSHub 自建实例（采集侧工具，不违反零后端）：`/weibo/search/hot`、`/weibo/user/:uid`、`/douyin/hot`；小红书路由需登录 cookie 基本不可用
- 搜狗微信：`https://weixin.sogou.com/weixin?type=2&query=王晰`（公众号文章，低频可用，反爬需 SNUID）

## 三、Server酱 Turbo 限制

- **title**：最长 32 字符，超出截断
- **desp**：最长 32KB（约 1 万+ 汉字），超出截断
- **免费档**：每日 5 条（以实际套餐为准）
- 分片策略：标题只放关键信息（`王晰|微博新增2条`）；desp 主动截到 ~30KB，全文放站内页；超限按来源拆 2 条

## 四、推荐落地路线（优先级）

1. **P0** 微博移动端 JSON 搜索（1 次/小时）
2. **P0** 三大热榜 JSON（微博热搜/头条/抖音，各 1 次/小时）
3. **P1** 扩展 Bing 关键词组（`site:mp.weixin.qq.com`、`site:weibo.com 王晰 巡演/新歌/官宣`）
4. **P1** RSSHub 自建 `/weibo/user/:uid`（uid 需人工确认王晰本人微博）
5. **P2** 搜狗微信低频抓公众号（≤2 次/天）

**不做**：抖音/西瓜/小红书网页搜索（签名逆向）、百度/搜狗直接搜索。

## 五、纪律

所有新增渠道输出只写 `data/pending_web.json` 供人工核对、diff 只报新增、不落库、来源链接+时间戳随行、缺失标"待补"、提交前 git status 检查敏感文件。

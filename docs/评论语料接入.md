# 评论语料接入（受众层）

> 目标：把"平台评论"变成可检索的**受众语料**，与「本人语料」「声学实测」并列，而不是混在一起。
> 原则：**原文只进私有库，公开层只出聚合与短引用**。

## 一、链路

```
comment_ops.py collect --post <URL>        # 抓评论（登录态，两路采样）
        ↓  ops.db: comments 表（uid→hash，无昵称）
comment_ops.py export-corpus --post <URL>  # 标准 JSONL
        ↓  E:\wx\私有工具\comment_ops\exports\comments_<mid>.jsonl
corpus_ingest_comments.py --jsonl <...>    # 默认入私有库
        ↓  E:\wx\私有\王晰语料库\comments.db（posts + posts_fts + comment_meta）
检索：LIKE 关键词 / 最高赞 / 按帖 / 按日期
```

公开库 `data/corpus/corpus.db` **默认拒绝写入**；确需公开要加 `--yes-publish`，
且只应写入聚合/短引用，不得整段搬运。

## 二、字段契约（与 corpus.db 的 posts 表兼容）

| 字段 | 说明 |
|---|---|
| `key` | `weibo-comment|<comment_id>`，全局唯一 |
| `platform` | `weibo-comment` |
| `account` | **uid 的哈希**（不含昵称、不含主页链接） |
| `date` | 评论日期（相对时间按抓取日近似） |
| `text` | 评论正文（已去 HTML/表情标签） |
| `url` | 原帖地址（不是用户主页） |
| `media/transcript/duration` | 空（评论无媒体） |
| `songs` | 该帖推断出的曲名（可空） |
| `comment_id / likes / post_mid / fetched_at` | 附加元数据（仅私有库 comment_meta 使用） |

## 三、口径与局限（必须随结论一起写）

- **采样覆盖率**：微博深页有限制，实测大帖（413 条评论）可采到 **403 条（98%）**（PC 版 buildComments 深翻页）；
  所有"评论里 X% 说…"都必须标注覆盖率，不能说成全量。
- **转评混合**：转发时带的评论（`//@…`）也会被采到，分析时要单独标记。
- **相对时间**：`4分钟前/昨天` 只能近似到抓取日，跨月分析要谨慎。
- **删除可撤回**：用户删评后，私有库按 `comment_id` 同步删除（`delete from comments where comment_id=?`）。

## 四、现在能查什么

```bat
python -X utf8 project_b\corpus_ingest_comments.py --jsonl <...> --query 低音 --top 5
```

- 关键词命中（按赞数排序）
- 最高赞评论（舆论场里真正被看见的声音）
- 按帖/按日期的分布（下一步页面层用）

## 六、王晰广场短帖（weibo-search）

> 广场短帖是受众**自己发的**，不是回复；单独 platform 统计，不和评论区混。

```bat
python -X utf8 comment_ops.py search --q 王晰 --pages 30 --out links_wangxi_square.json
python -X utf8 comment_ops.py export-search --q 王晰
python -X utf8 project_b\corpus_ingest_comments.py --jsonl <search_wangxi.jsonl>
```

- 采集走 `s.weibo.com`（m.weibo.cn 搜索接口只回第 1 页，勿再用）；
- 相关性过滤：正文必须含「王晰/晰哥」，且名字出现在前 30 字；
- 入库 `posts.platform='weibo-search'`，与 `weibo-comment` 分表统计；
- 当前样本：234 条（2026-11 附近的广场短帖），页面 `voices.html` 单列一段；
- 也可当**评论目标**：`--out` 产出的 links 直接喂给 `collect-batch --links`。

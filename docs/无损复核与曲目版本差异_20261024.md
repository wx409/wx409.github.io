

## 六、环回录制链路（2026-10-24 实测）：低频被音效砍掉

QQ 音乐「臻品母带」下发的是加密容器（.mflac，173 MB / 246 s ≈ 5.9 Mbps，无 LaC 帧头，ffmpeg 拒绝解码），
不触碰 DRM 的前提下只能走声卡环回。环回实测结果：

| 项目 | 结果 |
|---|---|
| 录制 | 立体声混音 (Realtek) · 48 kHz / 24 bit · 330 s · 峰值 −24.7 dBFS |
| 自检（60 Hz + 1200 Hz 测试音） | 1200 Hz 正常，**60 Hz 相对衰减 54 dB** |
| 曲目频谱对照 | 40–200 Hz 能量 **0.00%**（320k 同曲 40–80 Hz 为 23.6%），1–4 kHz 反而占 19.2% |
| 结论 | 链路带陡峭高通，**不能用于低频测量**；嫌疑为 Nahimic 音效（服务需管理员权限才能停） |

处理：关闭 Nahimic / Windows「音频增强」后，先跑 project_b/loopback_selftest.py（放测试音、自己录、自己判）
通过 0 dB 判据，再录整曲。**未过自检的录制一律不进管线。**

## 七、母带环回复核（2026-10-24 晚，VB-Cable 链路）

链路：QQ音乐「臻品母带」（.mflac 加密）→ 客户端解密播放 → 默认输出切到 `CABLE Input`
→ `CABLE Output` 录 48k/24bit → 裁剪 35–281 s（246 s，与曲目时长一致）。

自检：60 Hz / 1200 Hz 幅度比 **−0.1 dB**（对比「立体声混音」的 −53 dB，说明低频完整）。
频段对照（环回 vs 320k mp3）：40–80 Hz 21.6% vs 23.6%，1–4 kHz 5.6% vs 5.8% —— 同一母带特征。

### 谐波列（混音层，最强帧）

| 分音 | 320k mp3（t=204.04s） | 环回母带（t=199.89s） |
|---|---|---|
| 1f0 61.6 Hz | **0.0 dB（最强）** | **0.0 dB（最强）** |
| 2f0 123.2 | −7.1 | −8.5 |
| 3f0 184.8 | −13.9 | −13.4 |
| 4f0 246.4 | −14.6 | −11.8 |
| 6f0 369.6 | −24.1 | −21.7 |

**结论：B1 61.6 Hz 的完整谐波列在母带上成立，且 1f0 是最强分音** —— 320k 的读数不是压缩产物。

### 一个必须记住的坑

同一份母带喂进自动管线，人声分离后最低音报成 **B3 246.1 Hz（= 61.6 × 4）**，音符仅 49 个。
原因不是他唱高了，而是 **demucs 人声轨把 60–90 Hz 基频削掉**，YIN 只能锁到第 4 谐波。
→ 极值音级一律以**原始混音谐波列**为准；自动管线在低音区的输出只作候选。

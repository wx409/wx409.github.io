# 王晰知识库 · 设计（第一性原理）

> 目标：GEO 生成式搜索引擎可引用、数字档案可验证、歌手生涯可查询的单一知识层。
> 原则：**实体 → 事实 → 关系** 三层分离；每层均可独立更新；构建脚本幂等可复用；来源与置信度必带。

## 一、为什么是三层

| 层 | 回答的问题 | 例子 | 来源 |
|---|---|---|---|
| 实体层 entities.json | "库里知道哪些对象？" | 王晰 / 《Low C的诱惑》 / 2026-08-23广州站 / 广东艺术剧院 / 乐华娱乐 | 各数据层 ID 归一 |
| 事实层 facts.json | "对象在何时具备什么属性？" | 王晰 2019-04-09 起 签约乐华娱乐（valid_from/to 表达时效） | timeline/长表/专辑 |
| 关系层 relations.json | "对象之间如何相连？" | 《一生守候》在 2026-08-23广州站 演唱（第18首） | setlists/entity_index/quotes |

时效性：事实带 `valid_from/valid_to`（如 海政2011→2018、乐华2019→2024、东演2025→至今），回答"当时他在哪个单位"。
置信度：`official(0.95) > verified(0.9) > single(0.7) > machine(0.5)`，与站内 live_repos level 对齐。

## 二、实体类型（8类）

person(王晰/工作室) · song(576) · album(8) · show(场次) · tour(一~六巡) · city(22) · venue(场馆) · org(机构) · event(生涯事件) · media(报道) · quote(金句) · tavern(小酒馆期次)

## 三、数据源映射（可复用构建入口）

| 源 | 产出 |
|---|---|
| data/timeline.json (34条) | 王晰事实层主干（出生/奖项/入职/专辑/巡演首场） |
| data/setlists.json (场次歌单) | show 实体 + song→show 关系（含曲序） |
| data/cities.json (22城) | city/venue 实体 + show 事实（含 tour_num/theme） |
| data/albums.json (8张) | album 实体 + 发行事实 |
| data/songs_meta.json (576首) | song 实体 + 统计事实（show_count/cities） |
| entity_index.json (434首) | song→show 关系补全 |
| data/live_repos.json | media 实体 + media→show 关系（official/verified/single） |
| data/quotes.json + data/tour/*.json | quote 实体 + quote→show 关系（verified/时间戳） |
| tavern/tavern_transcripts.json (107期) | tavern 实体 + 主题事实 |
| E:\wx（指数/微博语料） | 只登记数据资产索引，不内嵌（体量太大，按需查询） |

## 四、产出物

```
data/kb/entities.json   实体注册表（ID 规范：person:wangxi / song:一生守候 / show:2026-08-23-guangzhou）
data/kb/facts.json      原子事实（subject/property/value/valid_from/valid_to/source/confidence）
data/kb/relations.json  关系边（source/type/target/context/source_ref）
data/kb/kb_digest.md    面向 LLM 的纯文本事实摘要（GEO 直接可引用）
data/kb/manifest.json   统计 + 来源映射
```

## 五、构建与更新

```bash
python project_b/build_kb_graph.py          # 全量重建（幂等）
python project_b/build_kb_graph.py --no-qa  # 跳过问答库扩充
```
任何数据层更新（新场次/新专辑/新金句）后重跑一次即可，无需改脚本。

## 六、GEO 接入

- llms.txt 增加 KB 摘要链接（data/kb/kb_digest.md）
- qa_bank.json 由事实层规则生成（零 LLM），search.html 直接受益
- 结构化数据（JSON-LD）继续由各页面输出，KB 是其统一后端
